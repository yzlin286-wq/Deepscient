# 六个真踩过的坑

这六条不是想象出来的，是端到端演示真跑出来的。都记在这里，省你一次调试。

## 1. 脚本的工作目录是项目根，不是 run 目录

`science_exp_run` 执行时，cwd 是课题根目录。所以脚本里写 `open('data/raw.csv')` 就是你心里那个路径。

要往这次运行自己的目录里写东西，用环境变量 `DSH_RUN_DIR`（另有 `DSH_PROJECT_DIR`、`DSH_SEED`、`DSH_RUN`）。

早期版本 cwd 是 run 目录，学生写 `open('data/raw.csv')` 必然 `FileNotFoundError`——这是设计错误，已改。

## 2. Python 层默认断网

分析阶段不该联网。`DSH_LAB_NO_NETWORK=1` 会拦 `socket.connect`，所以任何"顺手下载个数据集"的脚本都会失败。

确实需要联网就显式传 `network: true`，运行记录里会写明。注意它管不住 `curl`、`wget` 这类子进程——那是另一个层面的事。

## 3. 骨架稿的注释不是正文

新建稿子里的 `<!-- TODO: 在这里引文献 [@somekey] -->` 是给你看的说明。解析器会把 HTML 注释剥掉再判定，所以不会因为注释里的示例引用而报"引用了不存在的文献"。

如果你的稿子里真有注释形式的待办，它们不会进 PDF，也不会被算进字数。

## 4. 上限为 0 表示不设上限

有的刊没规定图数上限。如果配置里写 0，判定时按"不限"处理，不会出现"图 1 张，超过上限 0 张"这种鬼话。

## 5. 假设检验不满足前提，是换检验，不是换到显著

`science_stats` 会先报 `assumptions`。正态性不过、方差齐性不过，它会给出 `warnings[].fallback`——比如 Welch t 检验不满足时退回 Mann-Whitney U。

两条纪律：

- 换了检验要在正文里写明换了什么、为什么；
- 不许反复换到 p < 0.05 为止。那是 p-hacking，审稿人一眼能看出来。

阶段 S7 的"假设检查"门认的是"你有没有跑过登记的 fallback"，不是"你的数据有多完美"。

## 6. 投稿要真图，skip 不等于过

`lint` 查图时会去稿件的 `figures/` 目录找文件。图在课题的 `figures/` 里不算数——投稿系统要的是稿件目录里那份。复制过去。

以及：面板上的灰点（skip）表示"没有证据可查"，不是"通过"。十二个阶段里出现 skip，说明这一步还没留下记录。

---

## 另外两个不是坑但容易误会的事

- **工具不是全局的**：33 个工具属于「科研模式」preset。别的 preset 的会话里看不到它们，这是设计。
- **面板和助手看的是同一份数据**：面板不缓存判定结果，每次刷新都重算门。两边不一致说明中间有写入——那正是该查的。
