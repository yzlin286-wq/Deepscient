# 十二个阶段与它们的门

流程定义在 `dsh-science/data/workflow.json`，共 12 个阶段、55 个门。每个门的判定都对着库里的真实状态，不是对着「聊到哪了」。

| 阶段 | 名字 | 一句话 | 典型产物 |
|---|---|---|---|
| S0 | 选题与范围 | 把「想做这个方向」缩成一句可以被否证的话 | `project.json` |
| S1 | 文献与现状 | 检索、定位缺口，并留下检索范围 | 文献库、缺口矩阵 |
| S2 | 设计与方案 | 选设计、写方案、列出威胁与对策 | `plan.json` |
| S3 | 样本量与预注册 | 算 n 或算 MDE；拿到预注册编号 | `prereg_ref` |
| S4 | 测量与工具 | 测量定义、单位、仪器、校准 | `protocols/` |
| S5 | 采集 | 数据从哪来、怎么编号、怎么防丢 | `data/` 原始文件 |
| S6 | 数据管理 | 清洗脚本、变量字典、缺失处理 | `code/`、`data/clean.*` |
| S7 | 分析 | 假设检验 + 效应量 + 稳健性 | `analysis` 记录 |
| S8 | 图与表 | 期刊尺寸、色盲友好、误差棒定义 | `figures/` |
| S9 | 写作 | 一份 `paper.md`，四个产物从它出来 | 稿件 |
| S10 | 内审 | 按审稿维度逐条自查 | 审计记录 |
| S11 | 投稿 | 覆盖信、要件、投稿系统格式 | PDF / DOCX / JATS |

## 门的四种状态

- `pass`：机器查了，过了。
- `fail`：机器查了，没过。阻塞级的不修就不能算这个阶段完成。
- `skip`：**没有证据可查**（没跑过、没留记录、或者库里没有这一列）。跳过不等于通过。
- `manual`：必须人来判断（伦理是否到位、作者贡献是否真实、cover letter 是否对路）。它永远不会变成 pass，但也不会消失。

阶段算「完成」的条件是：没有阻塞、没有警告、没有 skip。manual 不计入完成判定，但一直显示。

## 为什么有的门永远 skip

三类常见原因，都不是 bug：

1. **这个设计不适用**：非聚类设计不会有「设计效应已算」这一项。
2. **库里没有这一列**：比如「关键文献有全文」要读 `oa_pdf_url`，全库都没有就如实报没有。
3. **这一步本来就要你去外面做**：预注册要你去 OSF 提交、拿到编号再填回来。

面板和教练报的是同一件事。看到 skip，读 `detail` 里那句人话。
