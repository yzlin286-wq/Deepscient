# Versioning and Release

This page describes how DeepScient (repository `jiuwenswarm`) versions and publishes releases.

## Version rules

- Versions use `X.Y.Z` (for example `0.2.0`); pre-release suffixes such as `0.2.1.beta1` are allowed.
- Git tags are `v` plus the version (`v0.2.0`); tag, `pyproject.toml` version, and Release `tag_name` must match.
- Starting from `0.2.0`, desktop releases follow this scheme. Re-publishing the same version is allowed; the updater detects it by release timestamp.

## Single source of truth

The only version source is `[project].version` in the root `pyproject.toml`. Derived files are generated by `scripts/build_config.py`:

```bash
python3 scripts/build_config.py --check   # fail on drift
python3 scripts/build_config.py --version # print the current version
python3 scripts/build_config.py --sync    # regenerate derived files
```

Official build scripts run `--sync` automatically. Do not edit `jiuwenswarm/common/_build_config.py` by hand.

## Publishing

```bash
./scripts/release.sh --dry-run                 # validate and print only
./scripts/release.sh                           # build, tag, push, create Release, upload assets
./scripts/release.sh --skip-build              # reuse existing dist/ artifacts
./scripts/release.sh --branch feat/deepscient-v0.2 --remote github
./scripts/release.sh --notes-file /tmp/notes.md
```

Options: `--dry-run`, `--skip-build`, `--branch NAME` (default `feat/deepscient-v0.2`), `--remote NAME` (default `github`), `--notes TEXT`, `--notes-file PATH`.

The script requires a clean worktree, a matching local branch, a synchronized build config, and no existing `vX.Y.Z` tag locally or on the remote. It builds with `scripts/build-electron-exe.sh` (without `--test`) using `CCAGENT_PARTNER_APP_SECRET` from the environment, creates the tag, pushes branch and tag, then creates a GitHub Release and uploads assets.

## Asset names

| Platform | Asset |
| --- | --- |
| macOS | `DeepScient-{version}-macos.dmg` (required) |
| Windows | `DeepScient-{version}-windows.exe` |
| Linux | `DeepScient-{version}.tar.gz` |
| Account integration | `deepscient-oauth.zip` (optional) |

`release.sh` fails when the macOS artifact is not named `DeepScient-X.Y.Z-macos.dmg`, and lists the DMGs actually present in `dist/`.

## GitHub Release

- Repository: `yzlin286-wq/Deepscient`
- API: `POST https://api.github.com/repos/yzlin286-wq/Deepscient/releases`
- Tag `vX.Y.Z`, name `DeepScient vX.Y.Z`.
- Release notes priority: `--notes` > `--notes-file` > matching section in `CHANGELOG.md` > default text.
- `GITHUB_TOKEN` is read from the environment only; it is never printed.

## Updater timestamp fallback

Desktop update checks order releases by publication time so same-version republishes are detected. Missing timestamps no longer abort the check: the updater logs a warning and falls back to version comparison, for both a missing latest timestamp and a missing installed-version timestamp.

## Rollback

1. Delete the GitHub Release (web UI or `DELETE /releases/tags/vX.Y.Z`).
2. Delete the remote and local tag: `git push github :refs/tags/vX.Y.Z` and `git tag -d vX.Y.Z`.
3. Fix the problem and run `./scripts/release.sh` again.

For releases already in use, prefer bumping the patch version (for example `0.2.1`) over reusing the old version.

## Secrets

- Inject `CCAGENT_PARTNER_APP_SECRET` only through the environment or `<data root>/science/partner-app-secret` (one line, mode 0600).
- `jiuwenswarm/resources/science/partner-app-secret` is ignored by Git; the release script never prints or persists either secret.
- Use a least-privilege `GITHUB_TOKEN` scoped to this repository's contents and releases.
