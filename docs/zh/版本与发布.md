# 版本与发布

本文说明 DeepScient（仓库 `jiuwenswarm`）的版本号规则、版本单一来源、发布流程、资产命名以及回滚方式。

## 1. 版本规则

- 版本号遵循 `X.Y.Z`（如 `0.2.0`），必要时可带预发布后缀，如 `0.2.1.beta1`。
- Git 标签固定为 `v` + 版本号，例如版本 `0.2.0` 对应标签 `v0.2.0`。
- 标签名、`pyproject.toml` 的版本号、Release 的 `tag_name` 三者必须一致。
- 从 `0.2.0` 起，桌面端正式包使用上述规则；同一版本允许“同版本重发”（内容修复后重新发布），更新器按发布时间判断。
- 预发布版本由更新器按 `dev < alpha < beta < rc < pre < 正式版` 排序识别，发布预发布版本时需在 GitHub Release 上勾选 pre-release。

## 2. 版本唯一来源

版本号的唯一来源是仓库根 `pyproject.toml` 的 `[project].version`。派生文件由 `scripts/build_config.py` 统一生成：

- `jiuwenswarm/common/_build_config.py`（运行时读取的 `VERSION`、显示名、资产名）
- 根 `pyproject.toml` 与 `packages/jiuwenswarm-tui/pyproject.toml` 中带 `# build-config:` 标记的行

发布前必须确认派生文件没有漂移：

```bash
python3 scripts/build_config.py --check   # 漂移时报错并列出文件
python3 scripts/build_config.py --version # 只打印当前版本
```

修改版本时，只改 `pyproject.toml`，然后执行：

```bash
python3 scripts/build_config.py --sync
```

官方打包脚本（`scripts/build-electron-exe.sh`、`scripts/build-macos.sh` 等）会自动执行 `--sync`，不要手工修改 `_build_config.py`。

## 3. 发布前检查

- 当前分支与 `--branch` 参数一致，且工作区干净（`dist/` 已被 `.gitignore` 忽略）。
- 目标标签 `vX.Y.Z` 在本地与远端都不存在。
- 已配置远端（默认 `github`，即 `yzlin286-wq/Deepscient`）。
- 真实发布需要环境变量 `GITHUB_TOKEN`。
- 真实构建需要环境变量 `CCAGENT_PARTNER_APP_SECRET`。

## 4. 使用 release.sh 发布

脚本位置：`scripts/release.sh`。

```bash
# 只做校验和打印，不构建、不打标签、不推送、不调用 GitHub API
./scripts/release.sh --dry-run

# 完整发布：校验 → 构建 → 打标签 → 推送 → 创建 Release → 上传资产
./scripts/release.sh

# 复用 dist/ 下已有产物（跳过构建）
./scripts/release.sh --skip-build

# 指定分支与远端
./scripts/release.sh --branch feat/deepscient-v0.2 --remote github

# 自定义 Release 说明（否则依次尝试 --notes-file、CHANGELOG.md 对应版本段）
./scripts/release.sh --notes "修复桌面端更新检查"
./scripts/release.sh --notes-file /tmp/release-notes.md
```

参数说明：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--dry-run` | 关闭 | 只校验并打印将执行的命令 |
| `--skip-build` | 关闭 | 跳过构建，直接使用 `dist/` 中已有产物 |
| `--branch NAME` | `feat/deepscient-v0.2` | 发布所在分支，必须与当前分支一致 |
| `--remote NAME` | `github` | 推送目标远端 |
| `--notes TEXT` | 空 | 直接指定 Release 说明 |
| `--notes-file PATH` | 空 | 从文件读取 Release 说明 |

脚本按以下顺序执行：

1. 校验运行目录是仓库根、工作区干净、当前分支与参数一致、远端存在。
2. 执行 `python3 scripts/build_config.py --check`，并从 `pyproject.toml` 读取版本。
3. 校验本地与远端都不存在 `vX.Y.Z` 标签。
4. 非 `--dry-run` 且未 `--skip-build` 时，导出 `CCAGENT_PARTNER_APP_SECRET` 后调用 `scripts/build-electron-exe.sh`（不加 `--test`）。
5. 校验产物为 `dist/DeepScient-X.Y.Z-macos.dmg`。
6. 创建注解标签 `vX.Y.Z`，推送分支与标签。
7. 调用 GitHub Releases API 创建 Release，并上传 macOS 安装包（以及存在时的 `dist/deepscient-oauth.zip`）。

## 5. 资产命名

发布资产名必须与更新器的匹配规则一致：

| 平台 | 资产名 | 说明 |
| --- | --- | --- |
| macOS | `DeepScient-{version}-macos.dmg` | 必需，例如 `DeepScient-0.2.0-macos.dmg` |
| Windows | `DeepScient-{version}-windows.exe` | 由 Windows 打包链路产出 |
| Linux | `DeepScient-{version}.tar.gz` | 由 Linux 打包链路产出 |
| 账号对接包 | `deepscient-oauth.zip` | 可选，存在时随 Release 一并上传 |

`release.sh` 会强制检查 macOS 产物名。若实际文件名不同（例如历史脚本产出的 `DeepScient-setup-0.2.0.dmg`），脚本会失败并列出 `dist/` 下实际存在的 dmg，提示修正打包脚本，而不是手工改名后发布。

## 6. GitHub Release

- 仓库：`yzlin286-wq/Deepscient`
- API：`POST https://api.github.com/repos/yzlin286-wq/Deepscient/releases`
- `tag_name` 为 `vX.Y.Z`，`name` 为 `DeepScient vX.Y.Z`。
- 说明正文来源优先级：`--notes` > `--notes-file` > `CHANGELOG.md` 中对应版本段 > 默认文本。
- `GITHUB_TOKEN` 只从环境变量读取，不写入文件、不打印；创建失败时输出 HTTP 状态码与响应体（响应体不含 token）。

## 7. 更新器的时间戳回退

桌面端更新检查优先按 Release 的发布时间排序，以支持“同版本重发”。当缺少时间戳时不会中断检查：

- 最新 Release 的 `published_at` 为空：记录 warning，回退为版本号比较。
- 已安装版本的发布时间无法解析：记录 warning，回退为版本号比较。
- 双方时间戳都存在：按发布时间判断（同版本重发可被识别）。

因此发布时请确保 GitHub Release 正常生成 `published_at`；不要手工构造缺少时间戳的 Release。

## 8. 回滚

发布错误时按“先撤销 Release，再删除标签，修复后重新发版”的顺序处理：

```bash
# 1. 删除 GitHub Release（可在网页操作，或使用 API）
curl -X DELETE \
  -H "Authorization: Bearer ${GITHUB_TOKEN}" \
  -H "Accept: application/vnd.github+json" \
  "https://api.github.com/repos/yzlin286-wq/Deepscient/releases/tags/v0.2.0"

# 2. 删除远端与本地标签
git push github :refs/tags/v0.2.0
git tag -d v0.2.0

# 3. 修复问题后重新执行发布
./scripts/release.sh
```

注意：

- 删除标签后重新发布同一版本号是允许的；客户端依赖发布时间识别“同版本重发”。
- 若已发布一段时间且需要让客户端明确升级，建议递增补丁版本（如 `0.2.1`）而不是复用旧版本号。
- 回滚不会自动撤回已下载到用户机器的安装包，只会影响后续更新检查。

## 9. 密钥注入注意事项

- `CCAGENT_PARTNER_APP_SECRET` 只允许通过环境变量或 `<数据根>/science/partner-app-secret`（一行，权限 0600）注入。
- `scripts/release.sh` 只把环境变量导出给构建进程，不写入产物、不打印；不要把它放进命令行参数或提交到仓库。
- `jiuwenswarm/resources/science/partner-app-secret` 已加入 `.gitignore`，仍建议提交前用 `git status` 再次确认。
- `GITHUB_TOKEN` 建议使用最小权限的细粒度令牌（仅目标仓库的 Contents/Releases 写权限），发布结束后及时轮换。
- 构建日志、CI 日志与 Release 说明中都不要粘贴密钥。
